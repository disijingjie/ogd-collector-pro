Block 4：数据口径对照表 — "数据口径幻觉"可视化
核心学术发现：这是论文 v25 中提出的"数据口径幻觉"理论的直接可视化。
23 个平台使用了 6 类不同的统计口径（"数据集"、"数据目录"、"开放目录"、"接口"、"产品"、"登记"），直接比较这些数字会产生严重的口径偏差。例如山东 63,656 个"数据目录"与广东 97,528 个"数据集"不可直接比较大小——前者统计的是目录层级，后者统计的是数据集条目。

口径 A：数据集（Dataset Count）

适用平台：广东(97,528)、重庆(22,550)、上海(10,753)、贵州(9,042)、北京(4,454)、天津(3,344)、浙江(38,000·公共数据集)
可信度：高 | 与论文4E评估框架的"效力 Efficiency" 维度直接对应
不可直接比较：数据目录口径（口径B）、数据产品口径（口径E）

口径 B：数据目录（Catalog Count）

适用平台：山东(63,656)、海南(35,835)、湖北(24,119)、广西(10,162)、四川(9,115)、福建(6,722)、辽宁(4,120)、江苏(644)、内蒙古(219)
可信度：中-高 | 目录可能包含子目录嵌套，与"数据集"存在 1:N 映射关系
不可直接比较：数据集口径（口径A）— 山东63,656个"数据目录"≠广东97,528个"数据集"，两者的定义和粒度不同

口径 C：开放目录/开放数据目录（Open Catalog Count）

适用平台：山西(534·开放数据目录)、江西(534·开放数据目录)、吉林(303·开放目录)
可信度：中 | 这类平台通常数据量较小，但"开放"定语暗示可能仅统计了公开可访问的子集

口径 D：其他目录口径变体

适用平台：湖南(634·"目录条")、海南(35,835·"目录"而非"数据集")——同平台可能同时显示两种口径
注意：海南同时显示35,835个"目录"和334个"数据集"，两个数字差异达100倍。

口径 E：数据产品/数据登记（Product/Registration Count）

适用平台：河南(931·"数据产品"，由运营公司管理)、云南(428·"数据登记"，平台转型为登记中心)
严重警告：这两个平台的数据口径与其他平台完全不同。"数据产品"是经过加工封装后的服务单元，"数据登记"是目录登记条目，与原始数据集数量无可比性。
不可直接比较：所有其他口径。河南和云南的数据建议在论文中单独讨论，不纳入跨平台比较。

口径 F：动态渲染采集（Playwright专项）

适用平台：安徽(36,300·开放目录，2026-05-03 Playwright复采成功)。同时采集到：4,289.50万条数据总量、80.53万次累计下载、222.59万次累计调用。
状态：已攻克，已复采验证。旧版8000端口已停运，新版URL为唯一入口。Vue.js SPA架构需Playwright动态渲染。
方法论声明：本研究的 TOPSIS 和 fsQCA 分析在数据预处理阶段已对口径差异做了标准化处理（通过归一化和模糊集校准消解单位差异）。但论文 v25 第 8.4 节明确指出："下载量不等于经济价值，数据集数不等于数据质量，平台数不等于开放水平——这是数据口径幻觉的三个维度。" 本节将此理论发现直接可视化。
专项案例：安徽平台 — 动态渲染技术攻克全过程
为什么单独展示安徽？安徽平台是 23 省中最具技术挑战性的采集目标。其平台使用 Vue.js 单页应用(SPA)架构，数据需要 JavaScript 动态渲染后才能获取，传统的 Requests+BeautifulSoup 方法完全无法工作。攻克这一平台证明了本研究采集系统的技术覆盖面和诚实性。
第一阶段：传统方法失败 (2026-04-25)
使用 Requests + BeautifulSoup 访问旧版 URL (data.ahzwfw.gov.cn)，仅获取到空白 HTML 骨架。Vue.js 渲染的数据完全不可见。规则标记为 confidence:low，value:null。
第二阶段：URL 变更发现 (2026-04-27)
检测到安徽平台迁移至新版 URL (data.ahzwfw.gov.cn/dataopen-web/index.html)，同时确认平台架构为 Element UI + Vue.js 单页应用，需要浏览器环境执行 JavaScript。
第三阶段：Playwright 动态渲染 (2026-04-28)
部署 Playwright + Chromium 无头浏览器，等待页面 JS 完全渲染(networkidle)，提取首页统计面板中的"开放目录"数字。
第四阶段：采集成功 (2026-04-28)
成功采集到 36,300 个开放目录，采集方法标记为 playwright:动态渲染。这是本研究首次使用动态渲染技术，证明系统可处理 JavaScript SPAs 平台。
第五阶段：复采验证 (2026-05-03)
今天通过 Playwright 再次复采成功。确认数据稳定：3.63万个开放目录、4,289.50万条数据总量、80.53万次累计下载、222.59万次累计调用。旧版 8000 端口已彻底停运（显示"系统维护中"），新版 URL 为唯一入口。复采脚本：collect_anhui_playwright.py（已开源到 GitHub）。
技术意义：采集方法从"静态爬取"到"动态渲染"的扩展，使本研究覆盖了 Vue.js/React 等现代前端框架构建的平台。23 省中仅安徽一省需要此技术，但这一技术突破保证了样本完整性——如果跳过安徽，样本将缺失一个重要的中部省份数据点。
